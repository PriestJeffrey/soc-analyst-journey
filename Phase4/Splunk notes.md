### SPLUNK BASICS: Intro to Splunk 
1. Splunk is a unified data platform that allows teams to work together or individual to ensure that critical systems stay secure and available every time.
2. At the heart of splunk is the splunk index which has the machine data fro  sources such as servers, network devices and web applications. 
3. The splunk has a data search feature that can help users enter a query into the search bar. This can help user find values across multiple data sources using the splunk search language. 
4. The search results can be saved to reports which can provide insight to data and can be used to power dashboard panels. The knowledge gotten from the results can be organized and structured into data models which allow users to quickly visualize data and pivots without writing custom searches.
5. There is also an alert feature that helps you stay on top of your environment. Alerts help you to set custom triggers which can help you respond to triggers as soon as they occurs.

### Using splunk web 
1. when you log into the splunk enterprise, you'll be redirected to the splunk home app. It's a preconfigured environment that sits on top of your splunk instance.
2. the apps you see are defined by users with administrator role. The roles determine what a user is able to see or do and interact with.
3. there are 3 predefined roles in splunk enterprise. 
- Administrator role: the admin role is the most powerful. It can install app, ingest data and create knowledge objects for all users.
- Power role: The power role can create and share knowledge objects with al users of an app and perform real time searches.
- User role: The user role will only see their own knowledge objects and those that have been shared with them.
Splunk Cloud specific roles include SE admin, power, and user.

### Interface Components
The Search and Reporting app is the primary interface for data analysis. It consists of several key functional areas:

1. Splunk Bar: A persistent element used to switch between apps, manage configurations, monitor search jobs, and view system messages.
2. App Bar and Search Bar: Used for application navigation and executing search strings.
3. Time Range Picker: Enables users to retrieve events over specific historical periods.
4. Data Summary: Provides a breakdown of indexed data categorised by host (IP address or hostname), source (file path or network port), and source types.
5. Table Views: Offers a UI-driven method to explore data without using Splunk Search Processing Language.
6. Search History: Allows users to view and rerun past searches, with filtering options for today, the last seven days, or the last 30 days.

### Data Interaction
Once a search job is executed, users can interact with the returned events and fields to deepen their investigation.

1. Event Details: Events are displayed in reverse chronological order, with timestamps adjusted according to the user's account time zone settings.
2. Field Selection: By default, Splunk displays host, source, and source type; however, users can access all extracted fields via the info button.
3. Search Refinement: Clicking highlighted text within an event allows a user to add that term to the current search, exclude it, or launch a new search in a separate window.
4. Job Management: Users can save searches as knowledge objects or export data in raw, CSV, XML, or JSON formats. While standard search jobs remain active for 10 minutes, shared jobs remain active for seven days and are readable by all users.
